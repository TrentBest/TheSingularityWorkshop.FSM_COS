# Requirements, Tests, and Architecture Decisions

## Purpose
Connect human goals and technical contracts to the code and evidence that supports them.

For each important requirement/use case, link relevant API contracts, MicroBundles, implementation symbols, tests, diagrams, and architecture decision records (ADRs). A simple table is sufficient until graph scale makes a visual map useful. Identify requirements without tests and tests without a documented requirement when practical.

ADRs record context, decision, alternatives, consequences, status, and links to affected diagrams/tests. Keep constraints and invariants visible; do not rely on a diagram to carry the full rationale.

Evidence should distinguish source-checked claims, executed tests, benchmark results, runtime captures, and conceptual plans. Record revision and environment for reproducibility. A test passing proves only the behavior and scope it exercises.

## Acceptance
- Important goals/contracts have discoverable evidence links.
- Coverage gaps are visible.
- ADRs and invariants link to affected implementation and tests.
- No claim is promoted from intended to verified without matching evidence.
